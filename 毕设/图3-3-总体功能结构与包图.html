包间依赖关系说明
game-boosting-platform-ui → jmz-gateway ，经 request.js / Axios 发起 HTTPS 请求，网关路由至各后端服务
game-boosting-platform-admin-ui → jmz-gateway ，同上；菜单由 RBAC 动态生成，权限 Store 按角色过滤路由
jmz-security → jmz-common ，依赖公共工具类、JWT 工具与 TokenService
server-user → jmz-common ，依赖安全域对象、JWT 校验、Redis 缓存与 MyBatis-Plus 基类
server-order → jmz-common ； server-order → server-account （Feign），发布单/结算时调用账户服务完成冻结/划转
server-account → jmz-common ； server-account → Alipay SDK ，完成充值扫码、提现打款及回调验签
server-account → jmz-file ，充值凭证上传存储
jmz-file → jmz-common ； jmz-file → 阿里云 OSS ，文件写入对象存储并返回访问 URL
server-ai → jmz-common ； server-ai → 通义千问 API ，定价建议 / 文案优化 / 接单推荐
server-websocket → jmz-common ； server-websocket → Redis ，跨实例会话路由与消息 PubSub
jmz-gateway → jmz-register （Nacos），服务注册与动态路由刷新
架构说明
1
三层包结构：本图以 game-boosting-platform-service（后端多模块）、game-boosting-platform-ui（用户端）、game-boosting-platform-admin-ui（管理端）为顶层包，展示了系统从前端交互到后端业务再到基础设施的完整包划分。
2
后端微服务：各业务服务（jmz-security / server-user / order / account / file / ai / websocket）均独立部署，共享 jmz-common 中的工具类、Redis 模板、MyBatis-Plus 增强及 JWT 安全组件。
3
统一认证中心：jmz-security 作为独立的认证授权服务，负责用户登录、短信/图形验证码、Token 签发及 Spring Security 认证流程，为整个平台提供统一的身份认证能力。
4
公共模块复用：jmz-common 的子包（core / redis / mybatis / feign / security / config）被所有业务服务依赖，实现了横切关注点的集中管理，避免代码重复。
5
跨服务调用：server-order 通过 OpenFeign 调用 server-account 完成订单发布冻结资金、结算划转等跨域操作，保证订单状态与账户资金的一致性。
6
前端隔离：用户端与管理端为两个独立前端工程，通过 jmz-gateway 访问同一套后端 API，由 RBAC 权限模型在网关层与接口层双重控制访问范围。
7
即时通讯：server-websocket 基于 WebSocket 协议维护长连接，结合 Redis PubSub 实现跨实例消息路由与订单状态推送，减少前端轮询开销。
8
AI 能力：server-ai 封装通义千问接口，提供智能定价建议、订单文案优化与接单推荐三项能力，作为独立服务可按需扩展其他大语言模型。
9
基础设施：注册/配置中心（Nacos）、对象存储（OSS）、缓存（Redis）及外部渠道（支付宝、通义千问）为平台运行所依赖的第三方组件。
