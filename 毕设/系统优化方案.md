## 三、待优化功能清单

> 以下功能为需求文档要求但尚未在代码中完整实现，需在后续开发中补充。

### 3.1 【高优先级】管理员禁用/启用账户

**需求来源**：需求分析 2.2.3 第（3）节 — 用户管理模块需支持"禁用/启用账户"操作。

**现状**：`User` 实体中 `status` 字段已存在，但管理端无对应接口。

**待实现接口**：

| 接口 | 说明 |
|------|------|
| `POST /admin/user/{userId}/disable` | 禁用指定账户，填写禁用原因，更新 status=0 |
| `POST /admin/user/{userId}/enable` | 启用指定账户，恢复 status=1 |
| `GET /admin/user/{userId}/disable-history` | 查询禁用操作日志（关联操作记录表） |

**业务规则**：
- 禁用前检查该用户是否存在进行中的订单，若存在则拒绝禁用并返回提示
- 禁用操作写入操作日志表 `tb_operation_log`，记录操作人、操作时间、禁用原因
- 被禁用用户的所有 `Token` 在下次请求时失效，返回"账户已被禁用"

**数据库表设计**（如尚不存在）：

```sql
-- 账户禁用操作日志表
CREATE TABLE tb_account_disable_log (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL COMMENT '被禁用的用户ID',
    operator_id BIGINT NOT NULL COMMENT '操作人ID（管理员）',
    reason VARCHAR(500) NOT NULL COMMENT '禁用原因',
    status TINYINT NOT NULL DEFAULT 1 COMMENT '操作类型：1-禁用，2-启用',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_user_id (user_id),
    INDEX idx_operator_id (operator_id)
) COMMENT '账户禁用操作日志';
```

### 3.2 【高优先级】异常订单自动检测

**需求来源**：需求分析 2.2.3 第（4）节 — 订单管理需"自动检测异常订单并在列表中标红"。

**现状**：订单列表接口已具备筛选能力，但缺少异常检测逻辑和标红标识。

**待实现**：

| 功能 | 说明 |
|------|------|
| **异常检测规则** | 新增定时任务或监听器，检测以下异常：① 超时未完成（时限已过+48h宽限期）、② 用户投诉标记、③ 保证金不足、④ 资金流向异常 |
| **异常标识字段** | 在 `Orders` 表或查询 VO 中新增 `isAbnormal` 字段（0-正常，1-异常） |
| **异常原因字段** | 新增 `abnormalReason` 字段，说明异常类型 |
| **订单列表接口扩展** | `OrdersQueryDTO` 新增 `isAbnormal` 筛选条件，返回结果自动携带 `isAbnormal` 标识 |

**数据库表设计**：

```sql
-- 新增字段到 tb_jmz_orders（如需）
ALTER TABLE tb_jmz_orders ADD COLUMN is_abnormal TINYINT NOT NULL DEFAULT 0 COMMENT '是否异常：0-正常，1-异常';
ALTER TABLE tb_jmz_orders ADD COLUMN abnormal_reason VARCHAR(100) DEFAULT NULL COMMENT '异常原因';
ALTER TABLE tb_jmz_orders ADD COLUMN abnormal_time DATETIME DEFAULT NULL COMMENT '异常检测时间';
```

**定时检测伪代码**：

```java
@Scheduled(cron = "0 */5 * * * ?") // 每5分钟执行一次
public void detectAbnormalOrders() {
    // 1. 超时未完成订单检测
    // 2. 投诉订单标记
    // 3. 保证金不足订单检测
    // 4. 更新 is_abnormal 和 abnormal_reason
}
```

**待实现接口**：

**导出字段建议**：

```
订单ID | 订单编号 | 游戏名称 | 系统 | 区服 | 发单用户 | 接单用户 | 订单金额 | 安全保证金 | 效率保证金 | 订单状态 | 创建时间 | 完成时间
```

### 3.4 【中优先级】管理员收入统计

**需求来源**：需求分析 2.2.3 第（6）节 — 数据统计需包含"平台手续费收入、充值金额、提现金额"。

**现状**：`DashboardController` 已提供订单维度的统计，但缺少资金维度的管理员视角统计。

**待实现接口**：

| 接口 | 说明 |
|------|------|
| `GET /dashboard/income-summary` | 平台收入汇总：总充值金额、总提现金额、总手续费收入、本期收入等 |
| `GET /dashboard/recharge-trend` | 充值金额趋势（按日统计） |
| `GET /dashboard/withdraw-trend` | 提现金额趋势（按日统计） |
| `GET /dashboard/platform-fee` | 平台手续费收入统计（基于 `Orders.platformFee` 字段） |

**响应 VO 示例**：

```json
{
  "totalRecharge": "125000.00",
  "totalWithdraw": "98000.00",
  "totalPlatformFee": "8750.00",
  "todayRecharge": "3200.00",
  "todayWithdraw": "2100.00",
  "todayPlatformFee": "180.00",
  "balance": "17000.00"
}
```

## 六、后续工作建议

1. **优先完成 P0 级任务**：管理员禁用账户和异常订单检测是管理后台的核心诉求，直接影响平台运营安全性。

2. **论文中说明**：在论文第4章（系统设计）或第5章（实现）的"待实现功能"小节中引用本文档，说明当前版本的已完成功能和后续优化方向。

3. **自动化测试**：补充对核心业务流程（订单发布→接取→验收→完成）的自动化测试用例，覆盖资金冻结/解冻的关键路径。

4. **日志与监控**：对管理员敏感操作（禁用账户、仲裁裁决、强制关闭订单）增加操作日志记录，便于事后审计追溯。
