# 第1章 绪论

## 1.1 项目背景

近年来，随着电子竞技产业的蓬勃发展以及移动互联网的全面普及，网络游戏已成为全球范围内最具影响力的数字娱乐形态之一。根据中国音数协游戏工委发布的相关报告【1】，中国游戏市场规模持续扩大，用户数量保持稳定增长，游戏品类日益丰富多样。在这一大背景下，"游戏代练"与"游戏陪玩"作为游戏服务的衍生需求，逐渐形成了一个规模可观的细分市场。大量玩家因工作、学习等现实因素无暇投入足够时间提升游戏段位或完成特定任务，因而产生了对代练、陪玩服务的强烈需求；而另一部分具备高水平游戏技能的玩家则希望通过提供服务获取额外收入。这两大群体之间的供需对接，催生了游戏代练平台的兴起。

然而，传统的游戏代练服务在实践中暴露出诸多结构性矛盾与管理困境。从信息不对称的角度来看，发单用户往往缺乏对代练市场定价的了解，容易因价格设置过高或过低而导致订单无人问津或服务质量纠纷；从订单撮合的角度来看，平台缺乏有效的匹配机制，代练人员难以在海量订单中快速定位到最适合自己的任务，供需两端均承受着较高的搜索与决策成本；从服务质量的角度来看，传统代练流程缺乏标准化的履约跟踪手段，发单用户对代练进度缺乏实时感知，双方仅依赖事后验收，一旦出现争议难以溯源；从安全保障的角度来看，代练行为涉及游戏账号的安全、虚拟财产的保护以及保证金的管理，平台若缺乏完善的信誉体系与争议仲裁机制，则难以建立用户信任。上述问题的存在，制约了游戏代练服务的规模化与规范化发展。

与此同时，以大语言模型为代表的人工智能技术正加速向各行业渗透。大语言模型具备强大的自然语言理解、生成与推理能力【2】，能够在智能客服、内容生成、决策辅助等多个场景中发挥作用。将大语言模型能力引入垂直服务平台，不仅可以帮助用户进行合理定价、优化订单描述，还能够基于用户画像与订单特征实现智能推荐，从而有效缓解传统平台在信息匹配与决策辅助方面的痛点。

本课题提出设计并实现一套面向游戏代练场景的智能化平台系统。该系统以微服务架构为技术底座【11】，整合大语言模型能力【3】，围绕订单发布、订单匹配、在线沟通、履约跟踪与后台管理等核心环节构建完整业务闭环，旨在提升订单撮合效率、优化用户体验、增强平台可信度，为"AI + 垂直服务平台"的工程化落地提供可复用的设计思路与实现参考。

## 1.2 研究的内容

本文以游戏代练平台为研究对象，围绕系统的需求分析、架构设计、功能实现与智能化增强等方面展开研究工作，主要研究内容包括以下几个方面：

（1）系统需求分析与业务流程建模。通过对游戏代练业务的深入调研，明确了平台的核心用户角色（发单用户、代练人员、管理员）及其各自的功能诉求，对"发单—接单—履约—验收—仲裁"全流程进行了详细梳理与分析，提炼出订单管理、用户管理、消息通讯、信誉评价、客服仲裁等关键业务模块，并绘制了相应的业务流程图与用例图，为后续系统设计提供依据。

（2）系统架构设计与技术选型。针对游戏代练平台高并发、高可用的业务需求，本文采用前后端分离【10】与微服务架构【11】进行系统设计。前端选用 Vue3 框架【5】结合 Element Plus 组件库与 Pinia 状态管理方案，分别构建用户端（game-boosting-platform-ui）与管理端（game-boosting-platform-admin-ui）两个应用；后端以 Spring Boot 为基础框架【6】，依托 Spring Cloud 微服务体系进行服务拆分与治理，划分为网关服务（jmz-gateway）、用户服务（server-user）、订单服务（server-order）、账户服务（server-account）、文件服务（jmz-file）、AI 推荐服务（server-ai）以及 WebSocket 消息通讯服务（server-websocket）等多个独立模块。基础设施层面，采用 Nacos 作为服务注册与配置中心【7】，使用 MySQL 进行业务数据持久化【18】，通过 Redis 实现缓存加速【17】，借助阿里云 OSS 实现文件与图片的云端存储【16】，各服务之间通过 Spring Cloud OpenFeign 进行透明的服务间调用。

（3）核心业务功能实现。系统实现了游戏管理（大类、服务器、段位等基础数据维护）、订单发布（设置代练类型、目标段位、时限、价格、保证金等）、订单接取（代练人员浏览与筛选可接订单并完成接单操作）、订单履约（代练人员按要求完成代练任务并提交验收）、订单验收（发单用户确认结果并完成付款）以及订单撤销与客服仲裁等完整的业务闭环。同时，系统内置了完善的后台管理功能，支持管理员对游戏数据、订单数据、用户数据与异常订单进行集中管控。

（4）消息通讯与实时通知机制。为解决发单用户与代练人员之间信息传递滞后的问题，系统基于 WebSocket 协议【8】实现了浏览器端的实时双向通讯功能，支持聊天消息的发送与接收、消息已读状态反馈以及订单状态变更的实时推送，并通过 WebSocketSessionManager 结合 Redis 实现了跨服务会话路由与会话元数据管理，保障了消息通讯的可靠性与可扩展性。

（5）基于大语言模型的智能化推荐功能。本文引入了阿里云百炼平台的大语言模型服务【15】，在 server-ai 微服务中封装了 AI 交互核心能力，并在此基础上构建了三项智能推荐功能：其一为发单价格建议功能，系统根据用户填写的代练类型、目标段位、时限等订单信息，自动生成合理的价格区间建议与保证金推荐；其二为订单文案优化功能，系统对用户填写的订单标题与描述进行智能改写，提升订单信息的完整度与吸引力，从而提高接单率；其三为接单推荐功能，系统根据代练人员的擅长游戏、历史完成率、目标收益等个人画像信息，结合待接订单的特征进行智能匹配排序，向用户推荐最合适的三条订单并给出匹配度评分与推荐理由。上述智能功能均通过结构化提示词工程与大语言模型交互，并对模型返回结果进行 JSON 解析与容错处理，在保证响应质量的同时兼顾了系统鲁棒性。

（6）系统安全与认证机制。系统采用基于 JWT 的无状态认证方案【9】，前端通过 RSA 非对称加密将用户密码传输至后端进行登录验证【20】，登录成功后后端签发 JWT Token，前端将 Token 存入 Cookie 并在后续请求中附加，后端各微服务通过 Spring Security 与 jmz-security 模块进行统一鉴权，确保业务接口的访问安全。

## 1.3 论文结构

本文由六章内容组成，各章主要内容概述如下：

**第一章 绪论。** 阐述本课题的研究背景与行业背景，分析传统游戏代练平台存在的主要问题与痛点，说明本课题的研究意义与价值；概括本文的主要研究内容与所采用的技术手段；给出本文的整体组织结构及各章主旨概述。

**第二章 需求分析。** 对游戏代练平台的业务需求进行完整梳理与详细分析，包括业务描述、用户角色定义、核心业务流程分析与优化、系统的功能用例分析，并给出系统的功能包图与数据字典，为系统设计阶段提供完整的需求输入。

**第三章 系统设计。** 在需求分析的基础上，进行系统的总体架构设计与详细设计。包括系统技术架构选型与微服务拆分方案、各微服务的职责划分、核心业务模块的数据库表结构设计（概念类图、实体类关系图）以及关键接口的 API 设计。

**第四章 系统实现。** 详细描述系统各功能模块的具体实现过程，包括前端用户界面与交互设计的核心实现、后端各微服务关键业务逻辑的实现、消息通讯与 WebSocket 实时推送机制的实现，以及大语言模型智能推荐功能的完整实现细节，并给出关键代码示例与说明。

**第五章 系统测试。** 针对系统的核心功能模块制定测试方案，进行功能测试与验证，测试内容包括订单发布与接取流程测试、智能推荐功能测试、消息通讯功能测试以及后台管理功能测试等，并对测试结果进行分析。

**第六章 总结与展望。** 总结本文已完成的主要工作与取得的成果，客观评价系统目前存在的不足，并结合实际应用场景对未来可能的扩展方向与改进措施进行展望。
